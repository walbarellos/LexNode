## 2024-05-24 - HTML Parser Optimization
**Learning:** The application uses BeautifulSoup with the default 'html.parser' in several places. Since the application performs heavy web scraping of large judicial HTML pages, switching to 'lxml' provides a significant performance boost (up to 35-50% faster parsing times) without losing functionality. Also found an unused BeautifulSoup parsing in the fallback regex extraction.
**Action:** Replace 'html.parser' with 'lxml' where BeautifulSoup is used. Add 'lxml' to requirements.txt. Remove the unnecessary BeautifulSoup instantiation in `extrair_resumos_pesquisa_2grau` since it extracts via regex anyway.
## 2024-05-24 - JSF ViewState Caching & HTML Parsing Overhead
**Learning:** JSF frameworks (like the one used in TRF1 PJe) require a `javax.faces.ViewState` token. Redundant requests to obtain this token across sequential searches on the same crawler instance block the main request thread unnecessarily (~800ms penalty per search). Furthermore, using a full DOM parser like BeautifulSoup (`lxml`) on large HTML documents (~48KB) just to extract a single token takes ~20ms, whereas a targeted regular expression (`re.search`) takes <1ms.
**Action:** Cache the `_view_state` token in memory per instance for stateful crawlers. When extracting solitary tokens like CSRF or ViewStates from large HTML responses, use regex instead of `BeautifulSoup` to avoid the DOM parsing overhead, provided the HTML structure is somewhat predictable.
## 2024-05-24 - JSF ViewState Caching & Session Expiration
**Learning:** Caching the JSF `ViewState` across requests for the same crawler instance saves an expensive initialization GET request (~800ms) for subsequent queries. However, JSF sessions handle state lifecycle dynamically. Stale view states can lead to a `ViewExpiredException` on the server, breaking subsequent requests.
**Action:** When caching `ViewState`, always implement an error-handling mechanism wrapped around subsequent POSTs. If an HTTP error occurs during execution, clear the cached `_view_state`, re-initialize, update the payload with the new ViewState, and retry gracefully.
